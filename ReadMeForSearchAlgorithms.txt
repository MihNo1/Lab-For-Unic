Линейный поиск

Линейный поиск проходит по массиву последовательно, начиная с первого элемента.
Он сравнивает каждый элемент с искомым значением.
Если находит — возвращает индекс, если нет — возвращает -1.
Его плюс — простота. Минус — медленная работа на больших данных, потому что в худшем случае он проверяет весь массив.

Если спросят сложность:

Сложность O(n).

Бинарный поиск

Бинарный поиск работает только на отсортированном массиве.
Он делит массив пополам, сравнивает середину с ключом и отбрасывает половину массива.
Таким образом, количество проверок уменьшается в два раза на каждом шаге.

Сложность:

O(log n), поэтому он намного быстрее линейного.

Интерполяционный поиск

Этот алгоритм похож на бинарный, но он пытается вычислить примерную позицию элемента по формуле.
Он особенно эффективен, если данные распределены равномерно.
В этом случае он может работать даже быстрее бинарного поиска.

Сложность:

В среднем близка к O(log log n), но в худшем случае может быть O(n).
=================================== Бинарное дерево поиска ===========================
Я реализовал бинарное дерево поиска, где для каждого узла:
слева находятся меньшие значения, справа — большие.

Вставка

При вставке значение рекурсивно спускается влево или вправо в зависимости от сравнения.

Поиск

Поиск работает по тому же принципу — мы двигаемся влево или вправо, пока не найдём значение или не дойдём до пустого узла.

Удаление дерева

После тестирования я очищаю память рекурсивно, чтобы избежать утечки памяти.

Если спросят сложность:

В среднем O(log n), но если дерево вырождено — O(n).
=====================================Тестирование алгоритмов=================================
Для тестирования я использовал библиотеку chrono для измерения времени в микросекундах.
Каждый алгоритм запускался 5 раз для каждого размера массива.
Затем вычислялось среднее время выполнения.
